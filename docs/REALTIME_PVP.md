# リアルタイムたいせん（人と その場で 交互に 手を打つ PvP）

2026-11-27 追加。タイトルの いちばん上の ボタン「リアルタイムたいせん」。
ともだちと **あいことば（4けたの数字）** で 同じ へやに入り、その場で かわりばんこに たたかう。
これまでの 非同期の オンラインバトル（ほかの人の デッキ＝ゴーストと AI が たたかう）は **「ゴーストたいせん」** に 改名して そのまま残した（`js/ui/online.js`）。

| | リアルタイムたいせん | ゴーストたいせん |
| --- | --- | --- |
| あいて | その場に いる 人 | ほかの人が あずけた デッキを AI が うごかす |
| ファイル | `js/ui/rt.js`（通信・画面）＋ `js/ui/battle.js` の rt… | `js/ui/online.js` |
| サーバーが ない とき（GitHub Pages） | あそべない（「GASばんで あそべる」と 出して ゴーストたいせんへ 案内） | 見本デッキと れんしゅう |
| つかえる デッキ | 保管デッキ ＋ スターターデッキ 6種 | 保管デッキ だけ |

## 1. あそびかた（子どもの 画面）

1. タイトル →「リアルタイムたいせん」。なまえ（定型語 2つの 組み合わせ。ゴーストたいせんと 同じもの）と デッキを えらぶ。
2. ひとりが「へやを つくる」→ 4けたの あいことばが 大きく出る。ともだちに 口で 伝える。
3. もうひとりが「あいことばで 入る」→ 画面の 数字ボタン（キーボードは 使わない）で 4けた 入れて「入る」。
4. ふたり そろうと「あいてが きまった！」。先手は サーバーが くじで きめる。
5. かわりばんこに ターンを すすめる。あいての ライフ 20 を 0 に すれば かち。おたがい 15ターンで 決着しなければ ひきわけ（ゴーストたいせんと 同じ）。
6. こうさんは 左上の ≡ →「こうさんする」（自分の番で なくても できる）。

- まちあいで 10分 だれも来ないと、へやは 消える（つくった人の 画面に しらせが出る）。
- はじめての子（チュートリアルが まだ）の タイトルには 出ない。チュートリアルを おえれば、ぼうけんを クリアして いなくても スターターデッキで あそべる。
- ランダムマッチ・観戦・チャット・フレンドは **ない**（6章に ランダムマッチの 案だけ 残す）。

## 2. ルール：ゴーストたいせんと ちがう ところ

カードの効果・「ぴったり！」・マナ・手札の補充・15ターンと ニクスの嵐 などの 核ルールは そのまま（`js/engine/game.js`・`js/data/enemies.js` の `pvp`）。ちがうのは つぎの 3つ。

1. **まもる側の ブロックは 自動**。こうげきされた側の クリーチャーは、ゴーストたいせんで「こちらが ゴーストを こうげきした とき」と 同じ きまり（`game.js` の `enemyBlocks`：たおせるか、たおされない ときだけ ブロック）で ブロックする。自分で ブロックを えらぶ ことは できない。
2. **あいての番には 何も できない**（インスタント・打ち消し・瞬速で ブロッカーを出す、は 使えない）。カードを タップして 説明を見る ことは できる。
3. **どちらの側も 同じ きまり**で うごく。ゴーストたいせんでは ゴースト側だけ 効かない ものが あった（ダメージを ふやす カード、敵が タップされたとき、など。`s.swapped` の 分岐）。リアルタイムたいせんでは ふたりとも「プレイヤー」として あつかう。

1・2 は、「自分の番で ない ときは 操作できない」と いう 交互進行に そろえた 結果で、**いまの実装の 制限**。ブロックを 人が えらべる ように するには、こうげきの とちゅうで あいての 答えを 通信で 待つ しくみ（6章）が いる。

## 3. 通信方式

### 3.1 前提

- サーバーは 既存の GAS（`gas/Code.gs`。元は `tools/gas_Code.gs`）だけ。Firebase などの 外部サービス・アカウント登録・課金は 使わない。
- GAS には WebSocket が ないので、画面が `google.script.run`（`js/ui/server.js` の `call`）で **短い間隔の ポーリング** を する。

| 場面 | 間隔 | 関数 |
| --- | --- | --- |
| まちあい（へやを つくって 待つ） | 3秒 | `mtgRtSync` |
| たいせん中 | 2秒（自分の 操作が あれば 0.1〜0.15秒後に すぐ 送る） | `mtgRtSync` |

### 3.2 送るもの：操作ログ ＋ 通し番号（状態は 送らない）

**場の状態（ライフ・手札・戦場）は いっさい 送らない。** 送るのは「何を したか」だけ：

```js
{ n: 12,                      // 通し番号（その人の 0, 1, 2 …）
  e: ['hand', 3],             // 入口：どこを タップしたか（手札の 3番め）
  a: [['s','c',0], ['m',[1]]],// その あと 出た まどで えらんだ 答え（1つめの まどで 0番めの ボタン、つぎの まどで 1番めの 相手）
  h: '1x9k2a' }               // たしかめの 数（操作の あとの 場の ハッシュ）
```

入口 `e` は 5種類：`['begin']`（ターンの はじめ）・`['act', ボタン名]`（こうげきする／ターン おわり など）・`['hand', 番号]`・`['perm', 'P'|'E', 番号]`・`['swipe', 自分の番号, 'face'|相手の番号]`。
答え `a` は 4種類：`['s','c',i]`／`['s','v',i]`／`['s','x']`（シート）・`['m',[…]]`（いくつか えらぶ）・`['d',[…]]`（わりふる）・`['n',数]`。

### 3.3 しくみ：決定的な ロックステップ

- サーバーが へやごとに **乱数の たね（seed）** と **先手** を きめて ふたりに 渡す。対戦開始時に、おたがいの **デッキ（カードID 20まい）** も サーバー経由で 渡る。
- ふたりの画面は、同じ たね・同じ デッキで 同じ `newGame` を つくる（つくった側＝host を P として 組み立て、入った側は そのあと 場を 入れかえる）。エンジンは 乱数を `s.rng`（たねつき）しか 使わないので、**同じ 操作を 同じ 順に 入れれば、ふたりの 場は 同じに なる**。
- 自分の番：いつもの `battle.js` の 操作（タップ・スワイプ・まど）を、入口ごとに 1つの「操作」として 記録して 送る（`rtDo`）。
- あいての番：届いた 操作を、場を 入れかえて（`rtFlip`）**同じ `battle.js` の 関数に そのまま 通して 再生** する（`rtApply`）。再生中は まど・演出・描画を 出さず、まどの 答えは 記録から 取る。再生が おわったら 場を もどして 描く。
- どちらの番も「プレイヤーの ターン」の 流れ（`beginPlayerTurn` → 操作 → `endPlayerTurn`）だけを 使う。ゴースト用の `enemyTurn`・AI は 使わない。
- **ずれの 検出**：操作ごとに 場の ハッシュ（ターン・乱数を 使った 回数・ライフ・山札と 手札の ならび・墓地の 枚数・マナ・戦場の カードの 状態）を くらべる。合わなければ、ふたりとも「しょうぶなし」で 終わる（点は 変わらない）。
- 描画の ための 計算（使える カードを 光らせる など）が 乱数を 進めない よう、リアルタイムたいせんの 描画中は 別の 乱数に 差しかえる（`render`）。
- **まどの 順番の きまり**：「攻撃したとき 占術」の ように、まどを 出した まま 先へ 進む 能力が ある（エンジンは 答えを 待たない）。ふたりの 画面で 順番が 変わらない よう、(1) 答えは まどを 呼んだ 順、(2) 答えが ルールに 届くのは ほかの 流れが 全部 止まってから（演出の 待ちが おわり、続きの 処理が 落ち着いてから）、(3) 1つの 操作は その 中で 出た まどが 全部 答えられるまで、と した（`rtRec`・`rtPlay`・`rtDo`）。これを 入れる 前は、ランダムデッキの 通しテストで 場が ずれた。
- **ブラウザの 種類**：確認は Chromium どうし だけ。ランダムに 相手を えらぶ ところ（`autoTargets`）は、ブラウザの 種類で 乱数の 回数が 変わらない まぜかたに した（リアルタイムたいせんの とき だけ。ほかの モードの 結果は 変えて いない）が、**Safari と Chrome の 組み合わせは 未確認**。もし ずれたら 上の 検出で「しょうぶなし」に なる。

### 3.4 相手の手札

画面に 出るのは 枚数だけ（「てふだ 4」）。**ただし 操作ログ方式の 性質上、ふたりの ブラウザの 中には 相手の 手札・山札の 順番を ふくむ 場の 全体が ある。** 開発者ツールを 使えば 見える。学校内の あそびとして 割り切り、のぞき見の 防止（サーバー側で 場を 持つ 方式）は していない。

### 3.5 切断・例外

| できごと | どうなるか |
| --- | --- |
| 自分の ポーリングが **5回 つづけて 失敗**（失敗の あとは 2秒 あけて やりなおす。すぐ 失敗する ときで 約 10秒、返事が 来ない ときは 1回 8秒 待つので 最長 約 50秒） | 対戦を 終了。結果の 画面に「サーバーと 5回 つづけて つながらなかった」。この端末の 記録は 変えない |
| 相手が しずか（操作が 来ない） | あいての番の あいだ「まちじかん 1:23」を 出す（相手が 最後に 操作してからの 時間） |
| 相手の 通信が 8秒 とぎれた | 「あいての つうしんが とぎれて いる… N びょう」を 出す |
| 相手の 通信が **45秒** とぎれた（ブラウザを 閉じた・電波が 切れた） | のこった側が サーバーに 申し出て、**のこった側の かち**（サーバーが 自分の 時計で 45秒を 確かめる）。もどって きた 相手には「まけに なった」と 出る |
| こうさん | すぐ まけ。相手は かち |
| ブラウザを 閉じる | `pagehide` で こうさんを 送ろうと する（届けば すぐ 決着）。届かなければ 上の 45秒の きまり |
| 場が ずれた／結果が くいちがった | しょうぶなし（点は 変わらない） |
| へやの データが キャッシュから 消えた | 「へやが なくなった」で 終了（記録は 変わらない） |

**できない こと（正直に）**：
- ページを 読みこみなおすと 対戦には もどれない（へやの 番号と ひみつの 番号を 端末に 保存して いない）。45秒で まけに なる。
- iPad で ほかの アプリに 切りかえる・画面を 消すと、ブラウザが タイマーを 止めるので、45秒で「いなく なった」と みなされる。
- `pagehide` の こうさんは、ブラウザが 通信を 送り出す 前に ページを 捨てる ことが あり、**届く 保証は ない**。
- 相手が つながったまま 何も しない（長考・放置）ときは 自動では 終わらない。まちじかんを 見て、こうさんで ぬけるしか ない（こうさんした側が まけに なる）。ターンの 制限時間は 付けて いない。

## 4. サーバー側（`tools/gas_Code.gs` → `gas/Code.gs`）

### 4.1 追加した 関数

| 関数 | 呼ぶ とき | 引数 → 返り値 |
| --- | --- | --- |
| `mtgRtCreate` | へやを つくる | `{ d: [カードID×20], n: [なまえ, なまえ], i: デッキID（任意） }` → `{ c: あいことば, k: ひみつの番号 }` |
| `mtgRtJoin` | あいことばで 入る | `{ c, d, n, i }` → `{ k, st: 'play', side: 'g', seed, first: 'h'\|'g', foe: { d, n } }` |
| `mtgRtSync` | 2〜3秒ごと | `{ c, k, ops: [操作…], from }` → まちあい `{ st: 'wait', left }`／対戦 `{ st, side, seed, first, foe, ops, n, away }`／終了 `{ st: 'over', res, pts }`／`{ st: 'gone' }` |
| `mtgRtEnd` | 終わり | `{ c, k, why: 'play'\|'resign'\|'left'\|'desync'\|'cancel', r: 'w'\|'l'\|'d' }` → `mtgRtSync` と 同じ形 |

内部の 関数：`rtCode_`・`rtGet_`・`rtPut_`・`rtDrop_`・`rtSeat_`・`rtSide_`・`rtOther_`・`rtOut_`・`rtOp_`・`rtLate_`・`rtFinish_`。
`mtgResult` の 中に あった「デッキの点を 変える」部分を `deckPts_` に 切り出して、ゴーストたいせんと 共用に した（`mtgResult` の ふるまいは 同じ）。

### 4.2 デッキの 検証

`mtgRtCreate`・`mtgRtJoin` は、ゴーストを あずける とき（`mtgSubmitGhost`）と 同じ `checkDeck_` を 通す：20まい・サーバーが 知っている カードID だけ・合計 40点まで・同じ カードは 8まいまで・2色まで（旗が あれば その 3色）。合わなければ エラーで、へやは できない／入れない。スターターデッキ 6種（`js/data/samples.js`）は この きまりを 通る（`tools/gastest.mjs` で 確認）。

### 4.3 状態の 置き場所

へやは **CacheService（スクリプト キャッシュ）だけ** に 置く。スプレッドシートには 書かない（速い・自動で 消える）。シートに 書くのは、決着した ときの「デッキの点」だけ。

| キー | 中身 | 書く人 | 期限 |
| --- | --- | --- | --- |
| `rt:<あいことば>` | へや（状態・ふたりの デッキと なまえ・たね・先手・結果） | つくる・入る・終わる とき（LockService の 中） | まちあい 10分30秒／対戦中 2時間／終了後 15分 |
| `rt:<あいことば>:<h\|g>:n` | その人の 操作の 数 | 本人だけ | 2時間（決着で 消す） |
| `rt:<あいことば>:<h\|g>:o<k>` | 操作 40こずつ | 本人だけ | 同上 |
| `rt:<あいことば>:<h\|g>:s` | 最後に `mtgRtSync` を 呼んだ 時刻 | 本人だけ | 同上 |

- 操作ログと 時刻は **本人しか 書かない** ので、`mtgRtSync` は ロックを 取らない（2秒ごとの 呼び出しが ほかの 機能の ロックと ぶつからない）。へやの 作成・参加・決着だけ `withLock_`。
- 通し番号が「つぎの 番号」の 操作だけを 足すので、送りなおしが 重なっても 2回 入らない。
- 待機が 10分 続いた へやは、キャッシュの 期限と、`mtgRtSync`・`mtgRtJoin` の 中の 時刻の 確認の 両方で 捨てる。
- 画面ごとの「ひみつの番号」（32文字）を 持つ人だけが、その へやの 操作を 送れる。相手の ひみつの番号は 画面に 返さない。

### 4.4 結果と 点・ランキング

- 決着の しかた：ふたりの 画面が それぞれ 自分から 見た 結果を 送り、**そろったら 確定**（かち／まけ、または ひきわけ どうし）。くいちがえば しょうぶなし。片方だけが 送って 30秒 たったら、その 結果で 確定（相手は 画面を 閉じたと みなす）。
- 点は 既存の きまり（かち ＋2・ひきわけ ＋1・まけ −1、0未満なし）。**デッキID の ある 保管デッキ**（ぼうけんの あと サーバーに あずけた デッキ）は、ゴーストたいせんと **同じ「デッキの点」シートに 合算** する。だから **既存の ランキングに そのまま のる**（統合した）。
- **スターターデッキ** と、サーバーに あずけて いない 保管デッキ（デッキID なし）は、サーバーの 点は つかない。スターターは みんなが 同じ デッキなので、「だれの デッキか」を 表す ID が なく、ランキングに のせる 意味が ない ため。
- 端末の 記録：かちまけの 数は `mtg-online-v1` の `wins`・`losses`・`draws` に 合算（キーと 形は 変えて いない）。リアルタイムたいせん だけの かちまけは 新しい キー `mtg-rt-v1`（`{ w, l, d }`）。
- 注意：ゴーストたいせんと 同じく、結果は 画面からの 申告が もと。ふたりで しめし合わせれば 点を 動かせる（かち ＋2・まけ −1 なので、交互に こうさんすると 合計は ふえる）。学校内の あそびとして 割り切って いる。

## 5. 制限と 目安（正直に）

- **遅れ**：相手の 操作が 画面に 出るまで、ポーリング間隔（最大 2秒）＋ `google.script.run` の 往復（GAS では ふつう 0.5〜2秒ほど）。**合わせて 1〜4秒** くらい 遅れる 見こみ。格闘ゲームの ような 同時操作は できないが、交互に 手を打つ カードゲームには 足りる。**実 GAS での 計測は まだ して いない**（下の「確認」）。
- **GAS の 実行回数**：対戦中は 1人 2秒に 1回、1対戦（2人）で **毎秒 1回** `mtgRtSync` が 走る。10分の 対戦で 約 600回。まちあいは 3秒に 1回。
- **同時実行の 上限**：このウェブアプリは「デプロイした 先生の アカウント」で 実行される（`executeAs: USER_DEPLOYING`）ので、Google の「同時実行 1ユーザー 30」が **全員 合わせて** かかる。`mtgRtSync` 1回が 0.3秒なら、N対戦で 平均 0.3×N 本が 同時に 走る 計算。**目安として 同時 15対戦（30人＝1クラス）まで** を 想定。これは 計算上の 見こみで、実 GAS で 負荷を かけて 確かめた 数字では ない。こえると 呼び出しが 失敗し、5回 つづくと 対戦が 終わる。
- **キャッシュの 上限**：スクリプト キャッシュは 全体で 1000こ まで（こえると 期限の 近い ものから 消える）・1こ 100KB まで・期限は 最長 6時間で「目安」（早く 消える ことが ある）。1対戦で 使うのは 10〜20こ。ゲーム本体の キャッシュ（「ゲームを 最新に する」を 使うと 約 120こ）と 分け合う。へやが 消えると その 対戦は「へやが なくなった」で 終わる。
- 1日の 実行回数そのものの 上限は Google の 公開の 表には ないが、**クォータは 予告なく 変わる**。最新は <https://developers.google.com/apps-script/guides/services/quotas> と <https://developers.google.com/apps-script/reference/cache/cache> を 見る こと。
- **1対戦の 操作は 1人 4000こ まで**、1つの 操作は 1500文字まで（こえる 操作は サーバーが 受け取らない）。
- あいことばは 4けた（1万通り）。同時に 待って いる へやは 少ないので 当てずっぽうで 入られる ことは まれだが、**防いでは いない**（入られても 1戦 あそぶ だけ）。

## 6. 今回 作って いない もの・設計メモ

- **ランダムマッチ**（未実装）：案は、`rt:queue` キー 1つに「待って いる へやの あいことば」を 1つだけ 置く。`mtgRtRandom` は ロックの 中で、キューに へやが あれば そこへ `mtgRtJoin`、なければ `mtgRtCreate` して キューに 置く。あとは 今の しくみが そのまま 使える。
- **ブロックを 人が えらぶ**：`declareAttack` の あと、こうげき側が「あいての ブロックの 答え」を 待つ 操作（守る側が 送る 1つの op）を はさむ。こうげきの たびに 往復 2〜8秒 待つ ことに なる。
- **観戦・チャット・フレンド**：作らない。
- **再接続**：へやの 番号・ひみつの番号・たね・自分の 操作ログを 端末に 保存すれば、読みこみなおしても 操作ログを 最初から 再生して 復帰できる（サーバーには ログが 残って いる）。

## 8. パック＆バトルから あそぶ（2026-11-28）

パック＆バトル（`docs/PACKBATTLE.md` 20章）の ホームにも「リアルタイムたいせん」の 入口が ある。**しくみは 上の 1〜7章と まったく 同じ**（同じ `js/ui/rt.js`・同じ `battle.js` の 記録と 再生・同じ サーバーの 関数 `mtgRt…`）。ちがうのは 入口と デッキ だけ。

### 8.1 じっさいに オンラインで あそぶ ために いる こと（GAS の デプロイ）

サーバーは 1〜7章と 同じ `gas/Code.gs`（`mtgRtCreate`・`mtgRtJoin`・`mtgRtSync`・`mtgRtEnd`）。**パック＆バトル用の 追加の 関数は ない。**

**A. いつもの GAS ばん（ゲーム ぜんぶ）で あそぶ** ← ふつうは こちら

1. この 変更が `main` に 入った あと、`gas/README.md` の「たまに（サーバーの しくみ＝Code.gs が かわった とき）」の とおりに **`Code.gs` を 貼りかえて「新バージョン」で デプロイ** する（`mtgRt…` が 入った Code.gs に する。URL は かわらない）
2. 先生の アカウントで ゲームを ひらき、「開発モード（先生）」→「ゲームを最新にする」（ゲーム本体と `cards.json` が あたらしく なる。「魔法使いの夜」など あたらしい カードID を サーバーが 知る ために いる）
3. 子どもは タイトル →「パック＆バトル」→「リアルタイムたいせん」。ひとりが へやを つくり、もうひとりが あいことばを 入れる

**B. パック＆バトル だけの ページ（1ファイル版）で あそぶ**

1. `gas/README.md` の「はじめの準備（clasp）」の やりかたで、`index.html` の かわりに **`packbattle-standalone.html` の 中身を `index.html` として** 上げる（`Code.gs`・`cards.json`・`appsscript.json` は `gas/` の ものを そのまま）。「Code.gs だけを 貼る」やりかたは、サーバーが GitHub から `gas/index.html`（ゲーム ぜんぶ）を とって くるので、この 形には ならない
2. デプロイした URL を ひらくと、すぐ パック＆バトルの ホーム。「リアルタイムたいせん」が つながる
- ふたりは **同じ ページ（同じ 版）** を ひらく こと。カードの 中身が ちがうと、相手の デッキに 知らない カードが あって はじめられないか、とちゅうで 画面が ずれて「しょうぶなし」に なる
- A の ページ（ゲーム ぜんぶ）と B の ページ（パック＆バトル だけ）を **同じ Code.gs（同じ デプロイ）で くばれば、たがいに たいせん できる** はず だが、ためして いない。たしかめたのは 同じ ページ どうし だけ

**まだ して いない こと**：実 GAS への デプロイと、実 GAS での 遅れ・同時実行の 計測（5章と 同じ）。たしかめは 下の にせものの GAS だけ。
